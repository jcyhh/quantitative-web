# 兼容性契约索引

这里记录的是已经由真实环境验证、即使问题目前已解决也不能被后续实现无意删除的兼容性边界。它是[团队知识路由](./ai-skills.md#从问题到团队知识)中的运行时差异专用记录，不是待办、缺陷列表或浏览器 API 教程：每一条契约都必须能指出所属能力、必要行为和验证证据。

## 何时必须阅读

任务涉及浏览器、Electron renderer、设备或运行时差异时，先阅读本文件。包括但不限于：输入与键盘、剪贴板、文件选择或下载、媒体播放或采集、窗口与系统交互、计时与后台恢复、动画与高频交互。

若下方没有匹配的已登记契约，按项目既有规范实现即可；不要因为“也许会不兼容”预建能力封装、UA 判断、fallback 或 lint 禁令。首次遇到并确认的长期边界，再按本文件新增契约。

## 已登记契约

当前没有已由本项目真实需求验证的兼容性契约。

未来契约按领域新增为 `docs/compatibility/<capability>.md`，例如 `audio-playback.md`、`text-input.md` 或 `desktop-runtime.md`。只有出现实际能力和可复现证据时才创建对应文件，不预建空目录或模板文件。

## 新增或更新契约

当线上、真机、浏览器或 Electron 环境发现会反复影响实现选择的问题时，在同一任务完成以下事项：

1. 在拥有该能力的模块中保留唯一公共入口；业务调用方不得复制设备判断或降级逻辑。
2. 新增领域契约，写明适用范围、已验证环境与现象、根因或不确定性、必须保留的行为、禁止的简化方式、代码入口、自动化验证和人工复测步骤。
3. 为当前测试运行器可表达的可观察行为添加就近测试，例如降级结果、超时恢复、资源清理或状态恢复；不要用源码字符串匹配代替行为测试。
4. 只有已确认某个原生 API 绕过公共入口会造成回归时，才在独立任务中增加范围最小的 lint 规则；规则同时写明唯一允许入口。
5. 在本文件的“已登记契约”列出领域、触发关键词和链接，使新 Codex 上下文能找到它；同时更新受影响的 Skill、模块 README 或 ADR。

## 契约的最小内容

每个领域文件至少包含：

```md
# <能力> 兼容性契约

- 适用范围与触发关键词：
- 已验证环境与现象：
- 必须保留的实现/降级/清理规则：
- 不应采用的简化方式及原因：
- 唯一公共代码入口：
- 自动化验证：
- 人工复测环境与步骤：
- 替换或删除该规则的证据与关闭条件：
```

不要记录完整调试流水账、一次性日志或未经证实的传言；它们应留在 issue、任务讨论或临时诊断中。契约只保留会改变未来实现决策的结论和证据。

## 任务交接

触发本索引的任务必须在交接中列出：读取的契约、保留或改变的规则、已执行的自动验证，以及未执行的人工设备/运行时复测和原因。未触发时写明 `Compatibility impact: none`。
