# ADR 0004：可复用问题经验的任务路由

## 背景

AI 会倾向于使用通用、流行或简洁的方案，无法仅凭零散代码注释、聊天记录或旧提交得知项目曾经解决过的非直观问题。该风险不只存在于设备兼容性，也存在于领域计算、接口契约、架构边界、构建配置和运营约束。

## 决定

功能交付、跨切面变更和只读审查 Skill 都必须判断：本次发现或修复的问题是否已经被证实、并且会改变未来实现选择。满足条件时，将经验在同一任务中路由到正确位置：可执行问题进入 lint/测试，模块私有边界进入模块说明，运行时差异进入兼容性契约，跨模块取舍进入 ADR，当前不实施的事项进入待办。

Skill 负责触发判断和导航，具体知识保留在其适合的文档或执行检查中。未经证实的猜测、完整调试流水账与个人偏好不得升级为团队规则。

## 后果

每个新 Codex 上下文不必阅读全部历史，但任务一旦触发相关能力，就能由 Skill 找到已沉淀的经验。每条重要经验同时拥有至少一种验证或执行证据，降低被后续“更流行”的实现无意覆盖的风险。
