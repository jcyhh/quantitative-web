# 0009: 高德地图公共接入边界

## 背景

项目已经提供浏览器定位和 WGS-84 到 GCJ-02 的坐标转换，但缺少地图展示、地图选点、经纬度逆地址解析和导航入口。若页面各自加载高德 SDK、读取全局对象或解析原始响应，会重复处理环境凭据、坐标系、生命周期和第三方字段差异，也会让后续 SDK 升级直接影响业务代码。

## 决策

- 在 `shared/lib/amap` 建立唯一的高德地图技术入口，负责 JS API 2.0 按需加载、严格类型边界、逆地址解析、选点控制器和官方导航 URI。Loader 1.0.1 的类型声明与 CommonJS 实际导出存在差异，公共层会校验并归一化命名导出与默认导出。
- 在 `shared/ui/tld-amap-picker` 提供 React 选点适配器，负责地图容器、受控坐标、Marker、点击逆解析和卸载清理；确认/取消、表单和业务提交留在所属业务模块。
- 通过 `VITE_AMAP_WEB_KEY` 和 `VITE_AMAP_SECURITY_JS_CODE` 注入 Web 端凭据。两者是浏览器公开配置，必须在高德控制台限制部署域名，不得承载服务端秘密。
- 地图 JS API、选点和逆解析统一使用 GCJ-02。浏览器定位需要先通过 `shared/lib/location` 显式转换；导航 URI 允许调用方声明 GCJ-02 或 WGS-84。
- SDK 只在首次使用地图能力时动态加载。未使用地图的页面不承担初始地图脚本请求和 SDK 初始化成本。
- 业务只能消费公共结构 `AmapCoordinate`、`AmapAddress` 和 `AmapPointSelection`，不得依赖 SDK 实例、全局 `window.AMap` 或原始逆解析响应。

## 未采用的方案

- **页面直接通过 script 标签或 Loader 加载：** 未采用。会分散 Key、安全配置、插件清单、错误处理和加载缓存。
- **将地图并入位置模块：** 未采用。浏览器定位/坐标转换不依赖第三方地图，而地图 SDK、配额和地址服务具有独立生命周期。
- **调用 Web 服务端逆地理编码接口：** 当前未采用。前端已有地图展示需求，复用 JS API 的 Geocoder 可共享加载和坐标契约；若未来服务端需要隐藏配额或统一审计，应另建后端代理并保持公共返回结构稳定。
- **预加载完整高德 SDK：** 未采用。当前没有全局地图页面，按需加载可以避免所有路由承担第三方脚本成本。

## 影响与验证

公共层新增 `@amap/amap-jsapi-loader@1.0.1` 运行时依赖，并为逆解析、选点控制器、导航 URL 和 React 生命周期提供自动测试。构建与测试可验证类型、模块边界和资源清理，但不能证明真实 Key、域名白名单、配额、地图瓦片、地址准确度或移动端 App 调起；这些项目必须在配置有效 Web Key 的目标 HTTPS 环境人工复测。
