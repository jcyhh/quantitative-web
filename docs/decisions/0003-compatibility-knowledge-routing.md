# ADR 0003：兼容性知识的任务路由

## 背景

浏览器、Electron renderer、设备和运行时差异会让通用且流行的 API 选择在真实环境中失效。单纯将已经验证的降级、超时或资源清理经验写在零散文档中，新的 Codex 上下文无法保证会主动发现，后续改动容易删除稳定性保护。

## 决定

建立 `docs/compatibility.md` 作为兼容性契约索引。`AGENTS.md`、功能交付 Skill、跨切面变更 Skill 和审查 Skill 都在任务涉及相应边界时强制路由到该索引及其登记的领域契约。

每条契约只记录经过真实需求验证、会改变未来实现选择的结论，并绑定唯一公共能力入口、可自动验证的行为和必要的人工复测环境。业务代码不得自行复制降级逻辑；已证明的直接原生 API 绕过风险才可新增窄范围 lint 规则。

不创建一个必须由 Agent 自行选择的“兼容性 Skill”：它仍可能被漏选。兼容性检查应是功能交付、跨切面变更和审查流程中的触发式门槛。

## 后果

新 Codex 上下文不会被要求阅读所有历史兼容性文档，但触发高风险能力时必须读取相关契约并在交接中报告影响。当前没有真实的 Quant Lab 兼容性契约，因此不预建音频、录音或设备封装；首个经验证的问题出现时再创建对应领域文档、测试和必要的执行约束。
